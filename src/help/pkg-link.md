Load a package live from a source directory, instead of installing a copy

## Description

Link an R package's source directory into a library, instead of installing a
built copy of it. Every time the package is loaded afterwards, with
`library()`, `::` or otherwise, it re-reads the current code from that source
directory, so an edit takes effect the next time it is loaded, with no
reinstall. This is the same idea as an "editable install" in other language
ecosystems.

`rig pkg link <path>` creates the link; [`rig pkg unlink`](pkg.qmd) removes it.
`rig pkg list` marks a linked package with `(linked -> <path>)`.

The source directory needs a `NAMESPACE` file (run `roxygen2::roxygenise()`
first if the package uses roxygen comments) and must not already be a real,
non-linked package in the target library -- run [`rig pkg remove`](pkg.qmd)
on it first if it is.

## pkgload dependency

Loading a linked package needs the `pkgload` R package to be installed
somewhere the R session will find it -- the target library itself, or the R
version's default library. `rig pkg link` checks for it and refuses with the
exact `rig pkg install pkgload` command to run if it is missing, rather than
producing a package that fails to load.

## Compiled code

A source package with a non-empty `src/` directory is linked too. Its
compiled code is rebuilt every time the package is loaded (via
`pkgbuild::compile_dll()`, the same step `pkgload::load_all()` uses), so an
edit to `src/` takes effect on the next `library()` call the same as an edit
to `R/` does -- but recompiling takes real time, unlike a plain R source
re-read. The `pkgbuild` package is required in addition to `pkgload` for
this, and `rig pkg link` checks for it the same way.

## NAMESPACE freshness

`rig pkg link` copies the source's `NAMESPACE` file as it is at link time. If
it is generated by `roxygen2` and the source changes what it exports later,
re-run `roxygen2::roxygenise()` and `rig pkg link` again to refresh it -- rig
does not regenerate `NAMESPACE` itself.

## Reinstalling and syncing

`rig pkg install` and `rig proj sync` both refuse to replace a linked
package: run `rig pkg unlink` first if you want the name to go back to a
normal, repository-installed package.

## Which library

`--library` (`-l`) selects a non-default library. It takes either the name of a
library of the R version, see [`rig library list`](library.qmd), or the path of a
library directory. A library name is tried first, so prefix a relative path
with `./` (or use an absolute path) if it happens to share a name with a
library.

`--r-version` (`-r`) links into the library of another R version, instead of
the default one.

In [admin mode](../admin-vs-user-mode.qmd) the site and system libraries of an
R installation belong to the administrator, so linking into them needs `sudo`
(an administrator account on Windows). Your own user library never does.
